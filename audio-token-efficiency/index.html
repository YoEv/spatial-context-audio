01

THE QUESTION

我们想验证什么？

最终目标是让多个 context 用更少的模型输入位置交流。眼下先回答一个更小、可核对的问题：音频编码器的表示，能否在压缩后仍保留两路内容，以及内容属于谁？

起点 / 已有现象

有些完整模型能回答混音问题

原网站测的是对话理解：听长录音、回答选择题。答对说明整个系统有能力，但不知道是哪一部分保存或读出了多路信息。

本轮 / 拆开检查

先拿掉长对话与开放问答

让两个人各说三个数字，答案可以逐项核对。只取现成音频编码器，训练一个小读取器，观察换编码器、压缩量和监督方式的影响。

之后 / 尚待验证

再回到真正的多 context

自然句子、更长内容、更多来源、压缩后才给的新问题，都还需要测。数字任务的成功只是一个起点。

本轮没有调用完整 FireRed／Qwen 大语言模型。 输出固定为六个数字，也没有让 LLM 当裁判。这里的高分不能直接当作长对话问答能力。
02

LISTEN, THEN TRACE ONE EXAMPLE

先听懂模型到底要做什么

两路都是真人数字录音。A 的第一个数字先起播，B 晚 0.6 秒；后两项同时起播。模型要按 A1、A2、A3、B1、B2、B3 的顺序还原答案。

真实测试音频 · 英语数字

① 模型实际听到的混音

模型只收到这一条。先听混音，再展开来源对照。

② 分别听 A、B，或连续听 A → B → 混音

单独来源与串联音频只供人理解，没有额外提供给混音读取器。

③ 检查内容与来源

这个面板固定为 8 位置、seed 0。下方总体结果使用三个种子。

三个例子按 FireRed 的 seed 0 结果挑选，用于讲解，不是随机抽样。整体准确率不能由这三例估计。播放文件为 PCM16 试听副本。

为什么用数字？

每个输出只有 0–9 十种可能，内容、顺序和来源都能精确评分。识别出“出现过 6 和 9”，却把两人的归属交换，仍然算错。

两个准确率分别看什么？

逐数字正确率：六个位置中答对多少。六项全对率：这一整条是否完全恢复。比如对了4个数字，前者是66.7%，这一条的后者是0。

03

THE EXPERIMENT, NOT THE FULL MODEL

从混音到答案，中间经过什么？

输入一条混音A＋B 的波形
冻结 · 不训练音频编码器 E变成一串声音特征
本轮训练共享模块 R适配六数字任务
本轮训练压缩器 P只留下 M 个向量
本轮训练小读取器 D输出 A、B 各三个数字

可以把它理解成：E 听声音，R 整理信息，P 写短笔记，D 从笔记还原答案。“冻结”是保持现成编码器的权重不变；每个编码器、预算和方案，都重新训练它后面的小模块。

4个位置是什么？

是4个连续向量，每个有128个数，两路来源合计4个。它们不是四个汉字、四个数字、四个离散码，也不是一段更短的 WAV。

128个数128个数128个数128个数

这里有两次不同的“编码”

现成编码器先把波形变成原生表示；我们再训练一个压缩器把它压成 M 个位置。EnCodec 等还含离散量化这一步，码本数与最后的位置数是两条独立的轴。

为什么有 B0、B1、B2？

它们是同一个编码器后面的三种训练／读取方案，不是三个预训练模型。

分源模块只处理隐藏特征，没有生成两条干净音频。B2 增加了参数与结构；这还不是容量匹配的因果对照。

训练、验证与测试如何分工？
4,096 条 · 训练

用已知的六个正确数字更新小模块；B1/B2 再加按来源的辅助识别损失。

512 条 · 验证

选择检查点；WavLM 第6层的完整补测也由验证成绩触发。

1,024 条 · 测试

所有新增训练完成后统一评分。说话人、录音与完整六数字组合在划分间隔离。

每配置三个随机种子；最多40轮、相同优化器与128维小读取结构。原生帧、单源和量化诊断只用一个种子。182是新增训练次数；42次旧运行明确复用。

这是 v1/v2 已查看过的测试集上的探索性扩展，尚需新的独立数据验证泛化。完整训练实现与实验记录保存在研究工作区。

04

WHAT EACH ENCODER WAS BUILT FOR

不同编码器，原本就在做不同的事

看懂三个积木就够了：卷积提取局部声音模式；Transformer／LSTM结合时间上下文；量化器把连续向量换成码本编号。它们怎样组合、按什么目标训练，会影响留下什么信息。

这些流程说明各模型的高层结构。彩色的“本轮取出”指出实验入口；大语言模型、波形生成器和完整 Inkling 模型都没有在本轮运行。固定版本 Qwen/A2R 的音频编码器525个张量逐值相同，因此只计一组权重。
补充：EncSep / GEncSep 是什么架构？

这是启发 B1/B2 的多说话人识别框架。高层主线是：混音 → 共享编码器 → 隐藏特征分源 → 文字解码器。原论文用 LSTM 与各来源的线性分支，把联合特征变成多路表示，并用各路转写施加 CTC 监督。

EncSep 主要借这些辅助分支改善训练；GEncSep 再把分开的表示拼接起来，供注意力解码器读取。它们分离的是编码特征，不必生成干净波形。本轮采用冻结编码器、较小的来源分支和六数字监督，只借鉴思路，没有复现原论文的完整 ASR 系统，也不把它们计作新的 tokenizer 权重。

05

WHY LAYER 6, AND WHY LAYER 12?

WavLM：为什么要选层？为什么是第6层？

WavLM Base+ 有12层 Transformer。每层都会产出一份表示：好比同一段声音经过12轮整理。整理得更深，不等于对我们的六数字任务一定更有用。

波形 → 卷积123456中间诊断点789101112标准末层输出

两层都是189帧 × 768维。选第6层没有把位置减半，也不是给 A/B 各分配一层；本轮提取仍执行完整12层，没有测提前退出的加速。

1 / 最初设定

第12层作主比较，第6层作诊断

末层是常规的现成输出。第6层取12层的中间位置，用来检查是否存在层差。没有先扫描所有层，再挑第6层。

2 / 只看验证集

88.02% 对 76.40%

保留原生时间帧、同样用 B0 读取时，第6层的验证逐数字成绩明显更高。因此在新测试评分前，固定追加它的27次预算实验。

3 / 最后看测试

有优势，也有明显波动

原生第6／12层测试为88.48%／75.49%。第6层 B2 在4位置的均值80.84%，种子范围却是73.70%–89.49%。两层结果都保留。

为什么中间层可能有用？

不同层会重组内容、音色和时序线索。WavLM 的混音预训练以主说话人的目标为监督，不是要求等权恢复所有来源；论文也指出不同任务会利用不同层。原论文 ↗

“某些来源线索更容易从中间层读出”是合理解释，但我们没有证明具体信息在第几层丢失。

现在能说第6层最好吗？

不能。这是中间层与最后层两个点的比较。更完整的选层应在训练／验证集上比较全部层或学习层混合，并在目标 M 和多个种子下确认，最后用独立测试集评估。

原生 B0 与压缩 B2 同时改变了预算和结构，它们的差值不能直接当作纯压缩损失。

MEASURED RESULTS

同样的内容，留多少位置，还能读对多少？

97.21%AuT＋B2，4位置逐数字正确
88.54%同配置，六项全部正确
100%文字压缩到4位置，两项均全对

在本任务里，AuT＋B2 压到4位置仍较稳定。WavLM 对层和种子敏感；两个 codec 的完整恢复率很低。“更多码本”“更深的层”“保留分源模块”，都没有普遍带来更高成绩。

点为三个训练种子的均值，误差棒为种子标准差，不是置信区间。横轴越往左，位置越少。文字虚线是同一个已知正确转写的学习压缩基准。

07

POSITIONS ARE NOT BITS

“压缩到4个位置”，到底省了什么？

模型输入位置

本任务的正确转写为11个 BPE ID。4个连续位置相当于位置数降到36.36%，但每个位置仍有128个浮点数。

11 个文字位置 → 4 个连续位置
2.75× 位置倍率

文字也可以学习压缩：本轮文字对照就是11个 BPE 位置，经学习压到4个连续位置，再读六个数字。

文件字节

4×128×float32 是2 KiB；11个 BPE ID 若用 uint32 保存只需44字节。共享词表、模型均不计入这两个载荷。

离散码：T × Q × log₂V bit
连续向量：M × d × b bit

T是帧数，Q是码本数，V是码本大小；M是位置数，d是维度，b是标量位数。这是序列化载荷，不是有效信息熵。

本轮还没有证明音频比 BPE 更高效。 文字基准已拿到正确内容与来源，音频需要先解决识别与混叠。当前压缩发生在共享 Transformer 后，尚未测完整 LLM 的时延或 KV cache；位置倍率不等于端到端加速倍率。
08

FROM DEEPSEEK-OCR TO OUR DESIGN TARGET

我们真正需要什么样的 multi-context 编码器？

DeepSeek-OCR 的启发是把“看清信息”和“以低成本留下少量表示”一起设计：先用局部处理保留细节，再在昂贵的全局处理前缩短序列。音频还必须保留所有来源及其归属。

信息保留

每一路都读得出来

高重叠、高内容密度和弱声音下，仍保留内容、顺序、来源。只改 B 的内容，A 的独立事实应保持稳定。

完整成本

前端和后级都要算账

少位置、多预算、参数适中；测整个路径的显存和时间。末端向量少，不能抵消前端已经花掉的计算。

可迁移性

能回答压缩后才出现的问题

从六数字扩展到未见句子、未知问题、更多来源与跨来源关系。不能只记住固定任务需要的答案。

根据当前结果，AuT＋多源监督＋预算压缩是可继续研究的起点；FireRed 用于跨家族复核，WavLM 用于层与来源线索诊断。是否需要自建编码器，要先定位瓶颈。

如果发送方本来就拥有独立文本，还应比较“分别编码后合并压缩”与“先混音再编码”，并匹配最终总预算。本轮未压缩 oracle 只作诊断，尚未完成这个对照。人工频带或可学习音频编码仍是候选，不是预设方案。

DATA & REPRODUCIBILITY

数据在哪里，哪些检查已经完成？

70组完整曲线 ↗全部预算、方案、均值与种子标准差 · CSV公开汇总数据 ↗逐种子、原生诊断、干预与3个例子的预测 · JSON完整静态曲线 ↗B0 / B1 / B2 × 两种评分 · SVG本页文件校验 ↗文件大小与 SHA256 · JSON

实验主机上保存174个实际压缩张量：每个为 1024 × M × 128 float32；还有 EnCodec Q8/Q2、SpeechTokenizer Q8/Q1 四个10-bit打包离散码文件。连续张量重放后 logits 完全相同，离散码解包后逐值相同。完整数据、特征、权重与检查点保留在研究环境。

运行成本与复核范围

在线为 batch=1，32样本×3次，包含波形构造、前处理、编码与读取，排除模型加载。codec 还计算诊断分支；WavLM 第6层仍运行全部12层。显存为 PyTorch peak allocated，含权重与临时张量，未隔离激活，也未扫描长输入。不能据此评价完整模型或长 context 成本。

新增特征以原生 float32、batch=1 提取，存为 float16。正式测试删除训练辅助头后的 logits 差值全部为0，四条新增在线路径与缓存结果逐值一致。不同编码器的预训练数据、规模、输入维度不同，比较用于选型，不是架构因果实验。
